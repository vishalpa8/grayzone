## What is built vs what is wired

**Built (`OemBatteryHelper`):** manufacturer detect, per-OEM instructions string, explicit
`ComponentName` intents for MIUI / ColorOS / iManager / OxygenOS / EMUI / Honor, Samsung → app
details, else → `ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS`. `openBatterySettings` try/catch returns
false — Principle III compliant at the helper boundary.

**Wired:** zero callers. Home and Onboarding launch
`Settings.ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` only. On the OEMs F-061 lists, that dialog is
widely reported as insufficient — autostart / "no restrictions" screens are separate. The helper
exists precisely because the team knew that; it was never connected.

**Detection after kill:** `ProtectionHealthRepository` exposes `vpnActive` / `overlayActive` /
`accessibilityActive` / `vpnReconnectPending`. Overlay and VPN writers exist in those services.
`updateAccessibilityStatus` is test-only (confirmed earlier). Nothing observes "we were killed by the
OEM" vs "user disabled a permission." After an OEM kill the notification is gone, services are dead,
and the next UI open may or may not restart them (E1 / F-066). The user is not guided.

## Wire-up constraints (must not be forgotten at fix time)

Already in F-061; restated so T067/T072 cannot ship a broken deep-link:

1. **`resolveActivity` before `startActivity`.** Every OEM branch builds a bare `ComponentName`.
   On API 30+ with the current launcher-only `<queries>` (`AndroidManifest.xml:10–15`), those
   packages are invisible → `ActivityNotFoundException` or a no-op. Falling through to
   `Settings.ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS` (the `else` branch at `:161–171`) is the
   correct fallback.
2. **Do not add `QUERY_ALL_PACKAGES`.** Play policy and the manifest comment forbid it. If a
   per-OEM `<package android:name="…"/>` query list is added, keep it minimal and documented.
3. **`canVerifyOptimization()` returns false for every OEM in `needsOemOptimization()`** (`:179–184`).
   The UI must not claim "you're protected" after the settings deep-link — only "we opened the
   screen; leave Autostart on."

Needs verification: on one Xiaomi and one Samsung device, confirm (a) generic battery dialog alone
does not stop kills, (b) the OEM component either resolves or the fallback fires, (c) sticky /
BootReceiver recovery after a kill. Severity already High; confirmed kill-without-guidance stays High
(silent protection loss with a built-and-unused mitigator).
