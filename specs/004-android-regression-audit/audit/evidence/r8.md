## F1. The `AppAccessibilityService` keep rule matches nothing

```text
AppAccessibilityService in seeds.txt : 0 occurrences
AppAccessibilityService in usage.txt : 0 occurrences
```

`app/proguard-rules.pro` contains `-keep class com.grayzone.app.service.AppAccessibilityService { *; }`.
Zero occurrences in **either** file means the class does not exist in the release input at all — the
rule is inert. The real class is `com.grayzone.app.service.GrayzoneAccessibilityService`.

**Classification**: stale configuration, not a release risk. → RU-08 / Principle I candidate (Low).

## F2. All manifest-declared components ARE retained

Present in `seeds.txt`:

```text
com.grayzone.app.MainActivity
com.grayzone.app.service.OverlayService
com.grayzone.app.service.GrayzoneAccessibilityService
com.grayzone.app.service.BootReceiver
com.grayzone.app.service.SessionExpiryReceiver
com.grayzone.app.service.vpn.AdBlockVpnService
com.grayzone.app.service.vpn.VpnHoldExpiryReceiver
```

**This corrects a pre-analysis assumption.** The absence of explicit keep rules for
`AdBlockVpnService` and the three receivers is *not* a defect: AGP generates keep rules from the
manifest automatically, and the evidence confirms all seven components survive minification. Any
finding claiming release-time stripping of a manifest component would be false.

**Classification**: no defect. It also means the two explicit keep rules in `proguard-rules.pro` for
`OverlayService` and `MainActivity` are redundant with AGP's generated rules. → RU-08 candidate (Low).
