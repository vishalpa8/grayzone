# Contract: Finding Record

**Feature**: `004-android-regression-audit`

The audit's externally-visible interface is its report. This contract fixes the shape of a single
finding so that FR-007's seven mandatory fields and SC-004's 100% compliance target are mechanically
checkable. Any record missing a mandatory field is a contract violation, not a stylistic choice.

## Required form

```markdown
### F-EXAMPLE — Overlay window leaks when the service is killed mid-friction  [Critical]  ⚠️ FORMAT ILLUSTRATION, NOT A FINDING

- **Review unit**: RU-05 (`service.overlay`)
- **Location**: `app/src/main/java/com/grayzone/app/service/OverlayService.kt` →
  `OverlayService.showFriction()` (lines 118–164)
- **Issue**: The `WindowManager` view is added on the success path but removed only in
  `onDestroy()`. When the system kills the service between add and destroy, the window token
  outlives the process and the user is left with an undismissable overlay covering the launcher.
  Protection appears "stuck on" and the only recovery is a reboot.
- **Trigger condition**:
  1. Grant overlay + accessibility permissions, set a 1-minute limit on a monitored app.
  2. Open the monitored app until the friction overlay appears.
  3. `adb shell am kill com.grayzone.app` (or trigger an OEM battery-manager kill).
  4. Observe the overlay remains on screen and no longer responds to its dismiss control.
- **Blast radius**:
  - *Callers*: `GrayzoneAccessibilityService.onAccessibilityEvent()` (via intent),
    `SessionExpiryReceiver.onReceive()`, `BootReceiver.onReceive()`. All three reach
    `showFriction()` through `OverlayService.onStartCommand()`.
  - *Process death*: the leak is caused by process death; the fix must hold no state that dies
    with the process.
  - *Config change*: rotation re-lays-out the window; a fix that re-adds the view on configuration
    change must not double-add.
  - *Foreground/background*: overlay is added while the app is backgrounded, so the fix cannot
    depend on Activity lifecycle.
  - *Cross-process*: the add is requested from `:a11y`; the window is owned by the main process, so
    the two can disagree about whether an overlay is showing.
- **Fix** (minimal): remove the view in `onStartCommand`'s early-return path and in a `finally`
  around the add, and make `OverlayService` idempotent on repeat `showFriction()` by keying on the
  currently-attached view rather than a boolean flag.
- **Test to add**: `jvm-unit` — `app/src/test/java/com/grayzone/app/service/OverlayLifecycleTest.kt`,
  asserting that the presentation's attach/detach bookkeeping returns to detached after an
  exception on the add path. Fails before the fix (flag stays `true`), passes after.
- **Existing test conflict**: none.
- **Verification**: `needs-verification` (evidence tier T4).
  - *Missing*: device execution of an `am kill` mid-overlay.
  - *Procedure*: steps 1–4 above on any API 29+ device.
  - *Severity effect*: confirmed → `Critical`; if the platform reaps the token automatically →
    `High`.
- **Build scope**: everyday-build
- **Constitution**: III (I/O/service boundary without explicit failure handling)
- **Observed against**: working-tree (uncommitted: `OverlayService.kt`)
- **Disposition**: reported
```

> The record above is a **format illustration**, not a finding. It uses plausible-looking content to
> pin down field shape and specificity. No claim in it has been verified, and it must not appear in
> the delivered report unless independently established.

## Field rules

| Field | Rule |
|---|---|
| Heading | `### F-### — <one-line issue> [<Severity>]`. Severity in brackets so the punch list can be generated by grep. |
| Review unit | Exactly one `RU-##`. A finding spanning units is split by root cause or recorded once with `affected_surfaces`. |
| Location | File path **and** function. A bare file path is insufficient. Line ranges included only where the file is not about to be rewritten by an earlier fix. |
| Issue | States the mechanism *and* the user-visible consequence. "This is not thread-safe" alone is a violation; the consequence is what drives severity. |
| Trigger condition | Numbered steps. Must include how to observe the defect, not merely how to reach the code. `adb` commands allowed and encouraged. |
| Blast radius | `callers` enumerated by name; the four mandatory risk axes always present; `cross_process`, `persistence`, and `release_only` present when applicable. |
| Fix | Smallest change that resolves the root cause. A rewrite requires an explicit justification line stating why patching fails. |
| Test to add | Names `kind`, path, and the assertion's before/after behavior. `instrumented` tests state that they cannot be executed here. |
| Verification | `confirmed` findings cite the code or tool output that confirms them. `needs-verification` findings carry all three sub-fields (missing, procedure, severity effect). |
| Build scope | `everyday-build` or `release-only`. Release-only findings are additionally listed in the release-only section. |
| Observed against | Commit SHA, or `working-tree` plus the uncommitted files involved, since 9 files are currently modified. |

## Prohibited patterns

These are the failure modes this contract exists to prevent:

- **Vague blast radius** — "used in a few places", "callers may be affected". Enumerate or state
  `none` with the search that proved it.
- **Speculation as fact** — any runtime assertion without a device, unless labelled
  `needs-verification` (FR-010, FR-025, SC-009).
- **Test placeholder** — "add a test for this". Name the file and the assertion.
- **Severity inflation** — `Critical` for style, dead code, or a defect with no user consequence.
  Dead code is `Low` unless it is actively reachable and wrong.
- **Rewrite by default** — proposing a component rewrite without demonstrating the minimal patch is
  insufficient (FR-014).
- **Silent scope drop** — a review unit with no findings and no `no-defect-found` outcome and no
  stated evidence of what was examined.
- **Merged root causes** — one record describing two independent defects, which corrupts the punch
  list and the fix tiering.
